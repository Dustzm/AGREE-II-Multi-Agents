# 中英文界面消息与兼容说明

## 语言边界

- UI、业务提示、错误、任务阶段和标准显示字段支持简体中文与英语。
- `AppraisalRunner.workflow_lang` 继续固定为 `en`，评价推理和报告正文保持英语。
- 用户内容、证据原文、模型输出、品牌和技术标识保持原语言。
- 报告接口只转换返回值中的标准显示字段；切换语言保留当前报告、标签页和评价结果，不改写报告文件。

## 消息契约

沿用 REST 的 `detail` / `message` 和 WebSocket 的 `content` 字段，增加可选描述和诊断：

```json
{
    "content": "✓ File parsed (2 pages)",
    "i18n": { "key": "status.parse_done_mineru", "params": { "pages": 2 } },
    "phase": "parsing",
    "state": "done"
}
```

HTTP 状态码、事件类型及已有文字字段的类型保持不变。422 的 `detail` 仍为数组，各项保留 `type`、`loc`、`msg` 并增加 `i18n`；不返回敏感 `input` 和 `ctx`。校验失败逐项显示原因。

后端 `app/i18n` 规范化 `zh`、`zh-CN`、`zh-TW`、`en`、`en-US` 等代码，解析 `Accept-Language` 权重，缺省英语。语言存放于隔离的请求上下文。公共前端请求层统一携带语言头；浏览器 WebSocket 使用 `lang` 查询参数。Chat 启动消息可显式指定任务语言，批量任务将语言保存在现有 `round_runtime_json.ui_language` 中，Worker 恢复后沿用；旧任务缺省英语。

前端使用 i18next 的 `server` 命名空间渲染后端消息键。界面状态保存描述和参数，渲染时翻译，已显示的错误、通知和连接测试结果可以随语言变化更新。未知键显示场景通用提示，原始信息进入诊断详情。

`diagnostic` 保留异常链并脱敏 API Key、密码、令牌、Bearer 凭据及含认证信息的 URL。界面诊断长度最多 4,000 字符；统一错误处理器及任务异常日志保留脱敏后的完整堆栈。原生 `alert` 已替换为通知或可展开错误区。

## 覆盖清单

| 范围 | 补齐内容 |
| --- | --- |
| 认证与权限 | 登录失败、登录失效、管理员权限及用户管理提示；登录失败与受保护接口 401 保持不同处理语义 |
| 上传与文件 | PDF / XLSX 类型、路径、缺失资源、保存失败、部分上传失败的逐文件原因 |
| 配置 | 保存、连接与健康测试、网络、无效响应、超时及异常诊断 |
| Skills | 查询、单项启用、批量启用、详情保存均返回请求语言的标题、描述、定位说明和维度显示字段 |
| Chat | 解析、预处理、智能体、条目进度、完成、部分失败、取消、错误；时间线描述同步存入本地存储 |
| 批量任务 | 状态和错误描述持久化、重试、停止、恢复、Worker 失败、事件重放及历史记录适配 |
| 报告与 PDF | 标准维度、条目标题、评分准则、未命名标题、PDF 加载 / 页面失败和诊断；英语推理保持原文 |
| Benchmark | 操作提示、错误、标准条目标签、日期 / 数字显示；语言切换不修改当前对比结果 |
| 其他 UI | 用户、智能体、手册、关闭按钮辅助文案、上传提示、中文词典残留英文及日期 / 数字格式 |

当前两种资源各有 730 个叶子键，其中 161 个后端消息键对应 `server` 资源。允许保留 AMA、AGREE-II、技术标识、代码、单位以及语言切换标识。

## 旧数据与调用方

- `AppraisalRunner` 新增可选 `on_message(message)`，旧回调签名及调用继续保留；Web 和 Worker 的新消息路径按 `phase` / `state` 更新阶段。
- SQLite 的 `batch_jobs` 和 `batch_job_items` 各新增可空 `ui_messages_json`。现有初始化机制通过检查列名幂等补列，不重建数据库。
- REST 和事件载荷增加 `step_i18n`、`error_i18n`、`diagnostic`。旧 `i18n:batch.*`、中英文文字和事件在集中适配器中读取；不批量改写历史数据。
- 前端兼容已有时间线字符串及本地持久化格式，旧错误在再次进入状态时脱敏。语言切换只影响显示，状态标识和结果不随文字变化。
- 新增的唯一直接开发依赖为精确版本 `vitest@3.2.7`；锁文件中已有依赖版本未升级或移除，生产依赖未改动。

## 后续维护

增加后端用户消息时同时维护 `app/i18n/catalog.py` 和两份前端 `server` 资源，并运行词典测试。业务错误在产生位置绑定键和参数，异常通过 `diagnostic` 传递。前端使用 `MessageView`、`notifyError`、`notifySuccess` 或描述对象保存消息，避免将 `t(...)` 的当前文字提前写入可持久化状态。
